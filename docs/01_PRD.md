# TimeTrace 产品需求文档（PRD）

- 文档版本：1.0（草案）
- 日期：2026-10-26
- 目标发布：v0.1.0 MVP
- 平台：Windows 10/11、Android 10+
- 项目性质：免费、开源、隐私优先
- 产品原则：本地优先、默认最小化收集、可解释的统计、可撤销的权限、用户拥有数据

## 1. 产品愿景

TimeTrace 是一款跨设备数字生活时间追踪工具。它在 Windows 和 Android 设备本地自动记录应用使用区间，在用户主动配对后通过局域网把 Android 的记录同步到 Windows，并提供统一时间轴、应用时长排行榜、按设备统计与重叠时长分析。

**一句话价值：让用户准确知道时间花在何处，且始终掌握自己的数据。**

## 2. 用户与场景

| 用户 | 主要需求 | 典型场景 |
| --- | --- | --- |
| 学生 | 学习与娱乐时间分布 | 复盘当天使用的应用及学习时段 |
| 开发者 | 编程与打断次数 | 比较 IDE、浏览器、即时通信工具的占用时间 |
| 数字生活记录者 | 长期可导出的原始数据 | 按日、周、月检索并导出记录 |
| 开源贡献者 | 可扩展、可复现 | 添加新的采集器、导出器和图表 |

## 3. 第一版目标（v0.1.0）

1. Windows 客户端可独立记录前台程序切换、非活动时间、锁定及恢复；数据写入 SQLite。
2. Android 客户端在用户授予“使用情况访问”权限后，可从系统 UsageEvents 补采应用活跃区间并写入本地 Room/SQLite。
3. Windows 能通过经过确认的局域网配对接收 Android 客户端上传的已完成区间，支持幂等重试和断网补传。
4. Windows 的仪表盘可查看当天总量、各设备时长、跨设备去重时长、应用排行榜、时间轴。
5. 用户可暂停/恢复采集、排除应用、按设备清除数据、导出 CSV/JSON、解除同步配对。

## 4. 功能范围

### P0 必须完成

| ID | 功能 | 用户故事 | 验收标准 |
| --- | --- | --- | --- |
| F01 | Windows 前台应用采集 | 我想知道电脑当前使用什么应用 | 应用 A→B 切换后，产生相邻区间；保存可重启恢复 |
| F02 | Windows 空闲与锁屏 | 我不希望离开电脑的时间被计为使用 | 空闲超过默认 120 秒、锁屏、睡眠时停止计入；阈值可配置 |
| F03 | Android 使用情况访问引导 | 我能自主授权并撤销 | 未授权显示说明和设置跳转；拒绝授权不崩溃 |
| F04 | Android 活动事件补采 | 我想知道手机使用了哪些应用 | 根据 Activity 和屏幕事件重建区间；锁屏后不计入普通前台活动 |
| F05 | 双端本地保存 | 断网也能记住记录 | 正常运行无需互联网；重启不重复导入已处理事件 |
| F06 | Windows 统一时间轴 | 我想按时间看两台设备的活动 | 可按日期/设备筛选；能够同时显示重叠活动 |
| F07 | Windows 数据统计 | 我想知道各应用时间分布 | 支持设备累计时长、跨设备去重时长、应用榜单 |
| F08 | 局域网配对与手动增量同步 | 我可以自主将手机数据同步到电脑 | 显式配对；HTTPS；上传失败保留原始数据；重复同步不重复计数 |
| F09 | 数据管理 | 我能暂停、排除、导出、删除 | 暂停时不创建普通活动区间；删除和解除配对由用户触发 |
| F10 | 开源交付 | 我可以构建并贡献 | CI 运行测试；README、构建说明、LICENSE、隐私说明齐全 |

### P1 争取完成（不阻塞 v0.1 发布）

- 自定义应用分类（学习、开发、娱乐、社交、其他）及规则优先级。
- 同局域网自动增量同步、同步状态和错误诊断。
- Windows 托盘驻留与开机启动选项。
- 周报、30 天趋势及批量导入备份。

### P2 后续版本

- 浏览器扩展，仅在授权后追踪域名；默认不收集完整 URL。
- 自托管互联网同步、多 Windows 或多 Android 设备、双向分类规则同步。
- AI 文字总结（明确同意后、本地统计优先）。
- Linux/macOS 扩展、插件 API、任务目标/提醒。

### 明确不做

- 键盘输入、屏幕截图、录屏、屏幕画面 OCR、后台偷采、隐蔽监听。
- 未经用户同意收集个人内容或自动上传云端。
- 将前台使用等同于绝对专注；不承诺 Android 秒级实时采集。

## 5. 页面设计

### Windows

1. **概览**：今日 Windows/Android 活跃分钟数、设备累计时间、去重后的占用时间、未识别区间提示。
2. **时间轴**：上方按设备多轨道展示；支持上一天/下一天、滚动、应用筛选、详情。
3. **统计**：应用排行、设备分布、按日趋势；总计指标有口径说明。
4. **数据管理**：排除应用、暂停、导出 JSON/CSV、按设备删除、存储占用。
5. **同步配对**：展示 Windows 接收端地址/二维码、设备清单、连接状态、立即断开。

### Android

1. **首页**：权限状态、今日应用时间分布、最近采集时间。
2. **应用列表**：应用名、包名、当天估计时长。
3. **同步**：查看已配对电脑、最后同步序号、立即同步、解除配对。
4. **设置**：打开使用情况访问设置、暂停记录、导出和删除。

## 6. 核心指标定义

- 活动区间采用左闭右开 `[start_ms, end_ms)` 的 UTC 毫秒时间戳。
- **应用活跃时长**：指定设备上经过平台状态过滤后的应用前台区间长度之和；不是“专注度”。
- **设备累计时长**：每台设备活跃区间在该设备内部去重后的长度，再跨设备求和。
- **跨设备去重时长**：所有设备活跃区间的并集总长度。
- **同时使用时长**：设备累计时长－跨设备去重时长（只有两台设备时可理解为二者重叠时长；多设备时是重复计入部分的总长度）。
- **不可观测区间**：事件丢失、权限撤销、采集器关闭、系统数据过期等造成的缺口，展示为未知，不推断为零。
- **日界线**：用户选择的显示时区的 00:00；跨日区间拆分后再按日聚合。

举例：Windows 09:00–11:00，Android 10:30–11:30，则设备累计 180 分钟、跨设备去重 150 分钟、重复计入 30 分钟。

## 7. 非功能性要求

- **数据所有权**：默认只存本地，不注册账号，不接入遥测和第三方分析 SDK；用户可以导出/删除。
- **安全**：局域网数据通过 HTTPS；配对须验证电脑证书指纹；设备持有单独授权凭据，可单独撤销。
- **稳定**：每次采集以事务提交；崩溃或重启不制造无限时长区间；记录中断/重启原因。
- **性能**：Windows 事件驱动优先，定期兜底检查；图表按日分页/聚合，避免全库逐条渲染。
- **容错**：权限关闭、系统时间变动、系统休眠、离线同步、设备重启均应有合理行为。
- **开源**：发布可复现构建步骤、CI、测试样例、数据格式版本、贡献指南。

## 8. 验收测试清单

- [ ] Windows A→B→A 切换，顺序和时长合理。
- [ ] Windows 锁屏、休眠、离开键鼠时停止普通活跃计时；播放视频的局限有明确提示。
- [ ] Android 拒绝、授予、撤销使用情况访问权限，应用均可正常运行。
- [ ] Android 连续使用 A、B，系统返回的事件能正确生成区间，重采不重复。
- [ ] Android 屏幕熄灭、解锁、设备重启不会产生异常超长区间。
- [ ] 手机与电脑断网 1 天后再同步，补传已保留记录且不重复。
- [ ] 同一批次上传两次，Windows 数据条目和统计值不变。
- [ ] Windows/Android 同时使用 30 分钟，跨设备并集统计不重复。
- [ ] 跨越午夜、夏令时调整、系统时间跳变，有测试用例。
- [ ] 用户关闭配对、清除数据、导出数据，行为符合说明。
