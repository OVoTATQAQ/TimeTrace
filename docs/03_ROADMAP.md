# TimeTrace v0.1.0 开发计划与 GitHub Issues 清单

> 假设：单人开发，每周投入约 10–15 小时，有 C++ 基础但需要学习 Qt、Kotlin、Android 权限和同步开发。此排期为参考里程碑，可根据实际进度调整。

## 1. 里程碑与验收

| 阶段 | 参考周期 | 可演示结果 | 发布门槛 |
| --- | --- | --- | --- |
| M0 项目搭建 | 第 1 周 | 双端运行 Hello World、CI 能构建 | README、LICENSE、编译指南、基础测试 |
| M1 Windows 采集 | 第 2–3 周 | 自动记录桌面应用区间 | 锁屏、空闲、切换、异常重启测试通过 |
| M2 Android 采集 | 第 4–5 周 | Android 本地应用使用统计 | 权限撤销、屏幕关闭、事件补采测试通过 |
| M3 协议与同步 | 第 6–7 周 | 手机手动上传到电脑，失败重传 | 认证、幂等、断网补传、安全测试通过 |
| M4 GUI 与发布 | 第 8–9 周 | Windows 统一时间轴，Android 设置页，安装包 | 数据导出/删除、README、安装指引和回归测试 |

关键路径：采集原型 → 跨端 schema → Android 区间规范化 → 安全配对与幂等上传 → 聚合 UI → 测试发布。

## 4. 测试矩阵

| 场景 | Windows | Android | 预期 |
| --- | --- | --- | --- |
| 应用切换 | 前台 A→B→A | 活动 A→B | 区间不互相覆盖异常 |
| 锁定/熄屏 | Win+L | 关闭屏幕 | 普通前台区间在边界处结束 |
| 空闲 | 3 分钟不输入 | 不适用同等定义 | Windows 超过阈值停止计入 |
| 权限撤销 | 不涉及专门使用访问许可 | 撤销 Usage Access | Android 进入不可采集状态并提示 |
| 离线 | 电脑关机 | 手机持续使用 | 手机保存已采集数据，重连后补传 |
| 重复上传 | 收同一批 3 次 | 上传同一批 3 次 | 结果只计一次 |
| 系统重启 | Windows 重启 | Android 重启 | 无跨启动的超长虚假区间 |
| 时间变化 | 人为调系统时钟 | 跨日期/时区 | 不产生负时长，报表按显示时区重算 |
| 数据管理 | 删除手机镜像数据 | 仍留在手机 | 不会静默从旧同步游标补回已删除历史 |

## 5. 发布检查（v0.1.0）

- [ ] 支持 Windows 10/11 与 Android 10+，记录已测试的实际设备型号和 OS 版本。
- [ ] Windows 新系统用户无开发环境也能运行安装包；Android 用户能安装签名 APK。
- [ ] 用户须主动授予 Android 权限才能采集；不会偷偷打开同步。
- [ ] 设备时间轴可以按日正确查询，跨设备重叠不重复计入去重时长。
- [ ] 同步加密、设备认证、失败重试、撤销配对可用。
- [ ] 无云端账号、广告或默认遥测；提供删除及数据导出。
- [ ] 对数据缺口和近似统计的风险做说明。
- [ ] 发布源码、构建方法、依赖许可、已知问题、changelog。
